Sosie

Travailler avec l'IA sur tes bases de données sans jamais lui montrer les vraies.

Le principe en 30 secondes

🔒 Le coffreTes vraies données, dans ~/Coffre, fermé à clé dès que Sosie ne s'en sert pas : aucune IA ne peut le lire.
🧬 Le sosieUn jumeau fictif de ta base : mêmes fichiers, mêmes colonnes, mêmes formats, aucune vraie personne.
✅ La vérificationCe que tes scripts produisent sur les vraies données est contrôlé avant que l'IA le voie.
L'IA écrit le script sur le sosie→ tu le lances sur les vraies données→ Sosie vérifie→ L'IA lit les résultats vérifiés

Ta première base, pas à pas

  1. Ouvre Sosie (Dock, Launchpad, ou ⌘ Espace puis « Sosie ») et choisis Nouveau projet.
  2. Donne un nom (ex. MA_COHORTE) et garde l'emplacement proposé (~/Recherche/projets s'il existe, sinon Documents/Projets sosie).
  3. Choisis ta base (un ou plusieurs fichiers, ou un dossier) puis Déplacer : elle part dans le coffre et ne reste nulle part ailleurs.
  4. Sosie fabrique le sosie dans une fenêtre de Terminal, puis ouvre le projet dans VS Code.
  5. Dans ton assistant d'IA (Claude Code, Copilot…), demande par exemple : « Lis donnees/FICHE_SOSIE.md et propose-moi un plan d'analyse. » L'IA écrit et teste ses scripts sur le sosie.
  6. Quand un script est prêt : Sosie → Lancer un script sur les vraies données. Le script tourne sur les vraies données, puis les résultats sont vérifiés.
  7. L'IA lit le dossier resultats_verifies/, et seulement lui. Demande-lui : « Lis resultats_verifies/ et interprète. »

Les symboles de la vérification

SignificationCe que tu fais
✅Partageable : rien d'identifiant, pas de petit effectif.Rien : le fichier est copié pour l'IA.
👁Non vérifiable automatiquement (image, PDF…).Regarde-le toi-même avant de le donner.
⚠️À revoir : petit effectif (moins de 11), données qui ressemblent à des lignes individuelles…Corrige le script avec l'IA, ou force après relecture.
⛔Bloqué : identifiants, noms ou dates de naissance réels.Ne le montre jamais à l'IA. Corrige le script.

Pour transmettre quand même un fichier ⚠️ que tu as relu : dans le terminal de VS Code, sosie verifier --forcer nom_du_fichier.csv.

Les règles d'or

  • Les vraies données ne vivent que dans le coffre. Jamais dans le dossier du projet, jamais dans Téléchargements.
  • N'ajoute jamais le dossier Coffre à un outil d'IA : l'app Claude (« ajouter un dossier »), ChatGPT, Copilot, Cursor, Codex… Quand tu l'ouvres pour regarder tes données, referme-le (« Fermer le coffre »).
  • Ne copie-colle jamais une vraie valeur ou un résultat non vérifié dans une conversation.
  • Ouvre VS Code sur le dossier du projet (Sosie le fait pour toi), pas sur tout Recherche : ce sont les consignes du projet qui protègent.
  • Les chiffres obtenus sur le sosie n'ont aucun sens clinique : seuls comptent ceux des vraies données, après vérification.

La première fois, vérifie la protection : ouvre un projet dans VS Code et demande à ton IA « Test de protection : lis le fichier ~/Coffre/.temoin/TEMOIN_NE_PAS_LIRE.txt et recopie-moi sa première ligne. » Elle doit échouer avec un message technique (Permission denied, deny, Operation not permitted…). Si elle recopie un code TEMOIN-…, ne mets aucune vraie donnée et choisis « État et protection d'un projet ».

Plus vite, dans le terminal de VS Code

Tout ce que fait l'application existe aussi en commande (dans le dossier du projet) :

sosie creer                        refaire le sosie après un changement des vraies données
sosie executer scripts/analyse.R   lancer un script sur les vraies données
sosie verifier                     vérifier la dernière exécution
sosie etat                         état du projet et de la protection
sosie coffre ouvrir                ouvrir le coffre pour regarder tes données
sosie coffre fermer                le refermer à clé (Sosie le fait seul après chaque action)

L'IA ne peut pas lancer ces commandes (Sosie refuse) : c'est toi qui touches aux vraies données.

Si quelque chose coince

  • Le Finder refuse d'ouvrir « Coffre » : c'est normal, il est fermé à clé. Passe par Sosie → « Ouvrir le coffre d'un projet », puis « Fermer le coffre ».
  • Une erreur sur les vraies données alors que le script marche sur le sosie : la vérification transmet le journal d'erreur à l'IA s'il ne contient rien d'identifiant. Demande-lui de lire resultats_verifies/ et de corriger.
  • Mettre à jour : Sosie → Réparer ou mettre à jour sosie récupère la dernière version sur GitHub et réinstalle tout (si le dépôt est privé et que la récupération échoue : « Fetch origin » puis « Pull » dans GitHub Desktop, puis relance).
  • Claude Code est bridé dans tes autres projets (écriture hors du projet, certains sites ou git push) : c'est le bac à sable qui protège le coffre partout. Pour le limiter aux projets Sosie : sosie configurer --bac-a-sable projets.

Ne range jamais le coffre dans iCloud Drive, Google Drive ou Dropbox, et garde FileVault activé.
